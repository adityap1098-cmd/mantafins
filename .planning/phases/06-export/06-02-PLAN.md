    Parse body as ExportConfig. Validate periodId present — return 400 if missing.

    Fetch data for ALL 7 sheets (fetch all even if not selected — buildWorkbook skips unselected sheets, and the data fetch is cheap for this data volume):
    - summary: query prisma for FinanceSummary data (aggregate from Sale, SaleItem, OperationalCost for the periodId)
    - saleRows: prisma.sale.findMany({ where: { periodId }, include: { items: { include: { product: true } } } }) — compute per-row metrics inline (same pattern as /api/sales)
    - customerRows: prisma.sale.findMany with groupBy customer + paymentLogs sum (same pattern as /api/receivables)
    - stockItems: prisma.productSnapshot.findMany({ where: { periodId } })
    - productMarginRows: from saleRows aggregate per product (same pattern as /api/finance productMargins)
    - customerDiscountRows: aggregate from saleRows per customer (same as /api/finance customerDiscounts)

    Assemble ExportData object. Call buildWorkbook(config, data).
    Await workbook.xlsx.writeBuffer(). Return new Response(buffer, { ... }) with correct MIME type and Content-Disposition.

    File naming: filename uses config.periodLabel directly (ExportClient constructs it using BULAN_ID from formatters.ts).

    Anti-patterns:
    - Do NOT use NextResponse.json() for the binary response — it will corrupt the buffer
    - Do NOT use workbook.xlsx.write(stream) — use writeBuffer() which returns Promise<Buffer>
    - The route file must NOT be in the Edge runtime — ExcelJS requires Node.js runtime
