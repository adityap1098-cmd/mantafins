<interfaces>
<!-- Receivables API response shapes from plan 05-03 -->

GET /api/receivables?periodId=X returns:
```typescript
interface CustomerReceivable {
  customer: string
  totalTransaksi: number
  totalTagihan: number
  totalTerbayar: number
  totalPiutang: number
  avgDiskonPersen: number
  sales: {
    id: string
    refNo: string
    date: string  // ISO
    grandTotal: number
    paid: number
    balance: number
    status: string
  }[]
}
// Response: { receivables: CustomerReceivable[] }
```

POST /api/receivables/payment body: `{ saleId: string, amount: number, note?: string }`
Returns 201: `{ success: true, saleId, newPaid, newBalance, newStatus }`

GET /api/receivables/customer?customer=X&periodId=X
Returns: `{ sales: SaleRow[] }` (same SaleRow shape as /api/sales)

Optimistic update pattern after payment:
- Update the specific sale in local state using the returned newPaid/newBalance/newStatus
- Recompute the customer's totalTerbayar and totalPiutang from updated sales array
- No full refetch needed
</interfaces>
